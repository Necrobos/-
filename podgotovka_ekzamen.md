# ЧАСТЬ I. ТЕОРИЯ ПО РАЗДЕЛАМ ПРОГРАММЫ

## 4.1. Математический анализ

### 1. Числовые последовательности и их пределы
Последовательность — функция натурального аргумента: `x_n = f(n)`. Число `a` называется **пределом** последовательности `{x_n}`, если для любого ε>0 найдётся номер `N`, такой что при всех `n>N` выполняется `|x_n − a| < ε`. Обозначение: `lim x_n = a`.

Свойства сходящихся последовательностей: единственность предела, ограниченность, предел суммы/произведения/частного равен сумме/произведению/частному пределов (если знаменатель не стремится к нулю). Монотонная и ограниченная последовательность сходится (теорема Вейерштрасса).

### 2. Предел функции. Непрерывность
`lim_{x→a} f(x) = A`, если для любого ε>0 существует δ>0: из `0<|x−a|<δ` следует `|f(x)−A|<ε`.

Замечательные пределы:
- `lim_{x→0} sin(x)/x = 1`
- `lim_{x→∞} (1+1/x)^x = e`

Функция непрерывна в точке `a`, если `lim_{x→a} f(x) = f(a)`. Точки разрыва:
- **устранимый разрыв** — предел существует, но не равен значению функции (или функция не определена);
- **разрыв 1-го рода** (скачок) — существуют конечные, но разные односторонние пределы;
- **разрыв 2-го рода** — хотя бы один из односторонних пределов бесконечен или не существует.

**Раскрытие неопределённостей.** Основные виды: `0/0`, `∞/∞`, `0·∞`, `∞−∞`, `1^∞`, `0^0`, `∞^0`.
Для `0/0` и `∞/∞` применяется **правило Лопиталя**: если `f,g` дифференцируемы и `lim f'/g'` существует, то `lim f/g = lim f'/g'`.
Неопределённости `1^∞`, `0^0`, `∞^0` сводятся к `0·∞` через логарифмирование: если `y = f(x)^{g(x)}`, то `ln y = g(x)·ln f(x)`, находим `lim ln y`, а затем `lim y = e^{lim ln y}`.

### 3. Производная
`f'(x) = lim_{Δx→0} [f(x+Δx)−f(x)]/Δx`. Геометрический смысл — угловой коэффициент касательной; физический — мгновенная скорость изменения.

Правила дифференцирования: `(u±v)'=u'±v'`, `(uv)'=u'v+uv'`, `(u/v)'=(u'v−uv')/v²`.
**Цепное правило (сложная функция):** если `y=f(u)`, `u=g(x)`, то `y'_x = f'(u)·g'(x)`.
**Производная обратной функции:** `(f^{-1})'(y) = 1/f'(x)`.
**Параметрически заданная функция** `x=x(t), y=y(t)`: `y'_x = y'_t / x'_t`.

Производные высших порядков: `f''(x) = (f'(x))'` и т.д.; формула Лейбница для `(uv)^{(n)} = Σ C_n^k u^{(k)} v^{(n-k)}`.

### 4. Формула Тейлора
`f(x) = Σ_{k=0}^{n} f^{(k)}(a)/k! · (x−a)^k + R_n(x)`, где `R_n` — остаточный член (в форме Лагранжа или Пеано).
Разложения при `a=0` (Маклорена): `e^x = Σ x^n/n!`, `sin x = Σ (−1)^n x^{2n+1}/(2n+1)!`, `cos x = Σ (−1)^n x^{2n}/(2n)!`, `ln(1+x) = Σ (−1)^{n+1} x^n/n`, `(1+x)^α = Σ C_α^n x^n`.

### 5. Экстремумы функций
**Необходимое условие**: если `x_0` — точка локального экстремума и `f` дифференцируема в ней, то `f'(x_0)=0` (стационарная точка), либо производная не существует.
**Достаточные условия**:
- 1-й порядок: смена знака `f'` при переходе через `x_0` (+→− максимум, −→+ минимум).
- 2-й порядок: если `f'(x_0)=0` и `f''(x_0)>0` — минимум, `f''(x_0)<0` — максимум.

Наибольшее/наименьшее значение на отрезке `[a,b]` ищется среди значений в стационарных точках, точках недифференцируемости и на концах отрезка.

### 6. Интеграл
**Неопределённый интеграл** `∫f(x)dx = F(x)+C`, где `F'=f`. Свойства линейности, табличные интегралы, методы: замена переменной, интегрирование по частям `∫u dv = uv − ∫v du`.
**Определённый интеграл** — предел интегральных сумм Римана; формула Ньютона–Лейбница `∫_a^b f(x)dx = F(b)−F(a)`.

### 7. Числовые ряды
Ряд `Σ a_n` сходится, если существует конечный предел частичных сумм `S_n`.
Необходимый признак: `a_n → 0`.
Признаки сходимости: сравнения, Даламбера (`lim |a_{n+1}/a_n| < 1`), Коши (радикальный), интегральный признак, признак Лейбница для знакочередующихся рядов (монотонное убывание `|a_n|` к нулю ⇒ сходимость), при этом остаток ряда лейбницевского типа оценивается: `|R_n| ≤ a_{n+1}`.

### 8. Функциональные последовательности и ряды
Равномерная сходимость: `f_n ⇒ f` на множестве `X`, если `sup_X |f_n(x)−f(x)| → 0`. Признак Вейерштрасса для равномерной сходимости рядов.
Степенной ряд `Σ c_n(x−a)^n` имеет радиус сходимости `R`, вычисляемый по формуле Коши–Адамара `1/R = lim sup |c_n|^{1/n}`; внутри интервала сходимости ряд можно почленно дифференцировать и интегрировать.

### 9. Функции нескольких переменных
Предел, непрерывность определяются аналогично (через ε–δ, но с евклидовой метрикой в R^n).
**Частная производная** `∂f/∂x_i` — производная по одной переменной при фиксированных остальных. Градиент `∇f = (∂f/∂x_1,...,∂f/∂x_n)` указывает направление наискорейшего роста.

## 4.2. Дифференциальные уравнения

**ОДУ** — уравнение, связывающее независимую переменную, функцию и её производные: `F(x,y,y',...,y^{(n)})=0`. Порядок — старший порядок производной.
**Общее решение** содержит произвольные постоянные (столько, каков порядок), **частное** — решение при конкретных значениях постоянных.

**Уравнение первого порядка**, разрешённое относительно производной: `y' = f(x,y)`.
**Задача Коши** — уравнение + начальное условие `y(x_0)=y_0`; теорема Пикара о существовании и единственности решения при непрерывности `f` и её липшицевости по `y`.

**Уравнения с разделяющимися переменными:** `y' = g(x)h(y)` ⇒ `dy/h(y) = g(x)dx`, интегрируем обе части.

**Линейное уравнение первого порядка** (важно для решения задач, хотя явно не выписано в программе):
`y' + p(x)y = q(x)`.
Решается методом **интегрирующего множителя** `μ(x)=e^{∫p(x)dx}`:
`(μ(x)y)' = μ(x)q(x)` ⇒ `y = 1/μ(x) · (∫μ(x)q(x)dx + C)`.

## Алгебра и геометрия

### Матрицы и определители
Матрица `A=(a_ij)` размера `m×n`. Операции: сложение, умножение на число, умножение матриц (согласованных размеров), транспонирование.
**Определитель** квадратной матрицы — число, характеризующее матрицу; вычисляется разложением по строке/столбцу через **миноры** и **алгебраические дополнения**: `det A = Σ a_ij·A_ij`, `A_ij=(-1)^{i+j}M_ij`.
**Ранг матрицы** — максимальный порядок ненулевого минора = число линейно независимых строк (столбцов). Базисный минор — ненулевой минор порядка, равного рангу.
**Обратная матрица** `A^{-1}` существует, если `det A ≠ 0`: `A^{-1} = 1/det A · A_adj`, где `A_adj` — присоединённая (союзная) матрица из алгебраических дополнений (транспонированная).

### Системы линейных уравнений (СЛУ)
`Ax=b`. Равносильные СЛУ получаются элементарными преобразованиями строк.
**Критерий совместности (теорема Кронекера–Капелли):** система совместна тогда и только тогда, когда `rang A = rang [A|b]` (ранг основной матрицы равен рангу расширенной). Если ранг равен числу неизвестных — решение единственно, иначе — бесконечное множество решений.
**Метод Гаусса** (последовательное исключение переменных): приведение расширенной матрицы к ступенчатому виду, обратный ход для получения решений.

### Векторные (линейные) пространства
Линейная зависимость: система векторов `v_1,...,v_k` линейно зависима, если существует нетривиальный набор `c_i`, такой что `Σc_iv_i=0`. Иначе — линейно независима.
**Базис** — максимальная линейно независимая система, через которую линейно выражается любой вектор пространства (разложение по базису). **Размерность** — число векторов в базисе.
**Матрица перехода** от базиса `e` к базису `e'`: координаты нового базиса в старом образуют столбцы матрицы `T`; связь координат вектора: `x_e = T·x_{e'}`.
**Линейная оболочка** `L(v_1,...,v_k)` — множество всех линейных комбинаций векторов. **Подпространство** — подмножество, замкнутое относительно сложения и умножения на скаляр.
Сумма подпространств `U+W = {u+w}`; пересечение `U∩W`; сумма прямая, если `U∩W={0}` (тогда `dim(U+W)=dim U+dim W`).

**Ортогональная проекция вектора y на подпространство L**, натянутое на базис `{g,h}`: ищем `p = αg+βh`, такой что `(y−p)` ортогонален и `g`, и `h` — то есть `(y−p, g)=0` и `(y−p, h)=0`. Это система линейных уравнений на `α, β` (см. разбор задачи 1.1 в Части II).

### Кривые
Способы задания: явное `y=f(x)`; неявное `F(x,y)=0`; параметрическое `x=x(t), y=y(t)`; в полярных координатах `r=r(φ)`.

## 4.3. Теория вероятностей и математическая статистика

**Случайная величина** — функция, ставящая в соответствие элементарному исходу число. Дискретная (принимает счётное множество значений) и непрерывная (принимает значения из интервала).
**Функция распределения** `F(x)=P(X<x)` — неубывающая, `F(-∞)=0, F(+∞)=1`.
**Ряд распределения** — для дискретной СВ таблица «значение — вероятность».
**Плотность вероятности** `f(x)=F'(x)` для непрерывной СВ; `P(a<X<b)=∫_a^b f(x)dx`.
Независимость СВ: `F(x,y)=F_X(x)F_Y(y)` (или `f(x,y)=f_X(x)f_Y(y)`).

**Математическое ожидание**: `M[X] = Σx_i p_i` (дискр.) или `∫xf(x)dx` (непрер.). Свойства: линейность `M[aX+b]=aM[X]+b`, `M[X+Y]=M[X]+M[Y]`.
**Дисперсия**: `D[X]=M[(X−M[X])²]=M[X²]−(M[X])²`. Свойства: `D[aX+b]=a²D[X]`, для независимых `D[X+Y]=D[X]+D[Y]`.

**Основные распределения:**
- Нормальное (гауссовское) `N(μ,σ²)`: `f(x)=1/(σ√(2π))·e^{-(x-μ)²/(2σ²)}`.
- Равномерное на `[a,b]`: `f(x)=1/(b-a)`.
- Показательное (экспоненциальное) с параметром `λ`: `f(x)=λe^{-λx}, x≥0`; `M[X]=1/λ`.

**Статистика:** генеральная совокупность — всё множество объектов изучения; выборка — часть, отобранная для исследования; выборочные значения — конкретные наблюдения.
**Эмпирическая функция распределения** `F_n(x)` — доля выборочных значений, меньших `x`; служит статистической оценкой `F(x)`.

## 4.4. Дискретная математика и математическая логика

**Булевы функции** `f: {0,1}^n → {0,1}`. Способы задания: таблица истинности, СДНФ/СКНФ, полином Жегалкина.
**Алгебра высказываний**: операции ¬, ∧, ∨, →, ↔; законы де Моргана, дистрибутивности и т.д.
**ДНФ** — дизъюнкция элементарных конъюнкций, **КНФ** — конъюнкция элементарных дизъюнкций.
**Полином Жегалкина** — представление булевой функции через ⊕ (сумма по модулю 2) и ∧: `f = c_0 ⊕ Σc_ix_i ⊕ Σc_ijx_ix_j ⊕ ...`.

**Замкнутость и полнота:** класс функций `K` замкнут, если суперпозиция функций из `K` снова лежит в `K`. Система функций **полна**, если через суперпозицию можно выразить любую булеву функцию.
**Теорема Поста**: система функций полна тогда и только тогда, когда она не содержится целиком ни в одном из пяти замкнутых классов: `T0` (сохраняющие 0), `T1` (сохраняющие 1), `S` (самодвойственные), `M` (монотонные), `L` (линейные).

## 4.5. Основы программирования

- **Синтаксис** — формальные правила построения конструкций языка; **семантика** — их смысл (что конструкция делает).
- **Типы данных**: примитивные (int, float, char, bool) и составные (массив, структура, объект). Статическая/динамическая типизация.
- **Структуры данных**: массив (последовательный доступ по индексу, O(1) чтение), связный список (O(1) вставка/удаление, O(n) доступ), стек (LIFO), очередь (FIFO), дерево (иерархическая структура, бинарное дерево поиска — O(log n) в среднем), граф (вершины+рёбра, представления — матрица смежности, список смежности).
- **Управляющие структуры**: последовательное выполнение, ветвление (if/switch), циклы (while/for/do-while), рекурсия.
- **Алгоритмы обработки данных**: линейный проход, разделяй-и-властвуй, динамическое программирование, жадные алгоритмы.
- **Поиск**: линейный поиск O(n); бинарный поиск в отсортированном массиве O(log n).
- **Сортировки**: пузырьковая/вставками/выбором O(n²); быстрая (quicksort) в среднем O(n log n), худший случай O(n²); слиянием (merge sort) гарантированно O(n log n); пирамидальная (heapsort) O(n log n).
- **Работа с файлами**: открытие/закрытие, режимы (чтение/запись/добавление), потоковый ввод-вывод, сериализация.

## 4.6. Объектно-ориентированный подход к разработке программ

**Принципы ООП**: инкапсуляция (сокрытие внутреннего состояния за интерфейсом), наследование (создание нового класса на основе существующего), полиморфизм (единый интерфейс — разные реализации), абстракция.
**Наследование**: производный класс получает поля и методы базового; **сфера действия метода** — область видимости (public/protected/private); **авторизация доступа** регулирует, кто может обращаться к членам класса.
**Расширяемость объектов** — добавление новых свойств/методов без изменения существующего кода (открыт для расширения, закрыт для модификации — принцип OCP).

**Статические методы** принадлежат классу, а не объекту, и не наследуют полиморфное поведение (не переопределяются виртуально — see задача 8.2).
**Виртуальные методы и полиморфизм**: метод, объявленный `virtual`, может быть переопределён (`override`) в наследнике; вызов через ссылку на базовый тип определяется **реальным типом объекта** (позднее связывание), а не типом ссылки — в этом суть полиморфизма (см. задачу 8.1).

**Динамические объекты** создаются во время выполнения программы (в куче, через `new`).
**Конструктор** — метод инициализации объекта при создании; **деструктор** — метод, вызываемый при уничтожении объекта (освобождение ресурсов).

## 4.7. Технология программирования

**Свойства программы**: работоспособность (корректность), читабельность, эффективность (по времени/памяти), затраты на разработку, стоимость сопровождения.
**Жизненный цикл ПО**: анализ требований → проектирование → реализация → тестирование → внедрение → сопровождение. Модели ЖЦ: каскадная, итерационная, спиральная, Agile.
**Нисходящее проектирование** (top-down) — от общей структуры к деталям; **восходящее** (bottom-up) — от готовых модулей к системе.
**Модуль** — независимая часть программы с чётким интерфейсом. **Структурное программирование** — использование трёх базовых конструкций: последование, ветвление, цикл (без `goto`).
**Отладка** — поиск и устранение ошибок; **тестирование** — проверка соответствия требованиям. Виды тестирования: модульное (unit), интеграционное, системное, приёмочное; методы «белого ящика» (по коду) и «чёрного ящика» (по спецификации).
**Шаблоны проектирования** (design patterns) — типовые решения повторяющихся задач проектирования: порождающие (Singleton, Factory), структурные (Adapter, Decorator), поведенческие (Observer, Strategy).

## 4.8. Базы данных и информационные системы

### Модели данных и СУБД
**СУБД** — система управления базами данных. Модели: иерархическая (дерево), сетевая (граф), реляционная (таблицы), объектная/объектно-ориентированная, объектно-реляционная (гибрид).

### Реляционная модель
**Отношение** (таблица) — множество кортежей (строк) с фиксированной схемой (атрибутами-столбцами). **Реляционная алгебра** — набор операций над отношениями: выборка (σ), проекция (π), соединение (⋈), объединение, пересечение, разность, декартово произведение.

**Нормализация** — процесс устранения избыточности и аномалий через разбиение отношений.
- **1НФ**: атомарность значений атрибутов.
- **2НФ**: 1НФ + каждый неключевой атрибут функционально полно зависит от всего первичного ключа (нет частичных зависимостей).
- **3НФ**: 2НФ + нет транзитивных зависимостей неключевых атрибутов друг от друга.
- **НФ Бойса–Кодда**: любая функциональная зависимость определяется потенциальным ключом.

### Модель «сущность-связь» (ER)
**Сущность** — объект предметной области; **атрибут** — свойство сущности; **связь** — ассоциация между сущностями (типы связей: 1:1, 1:N, M:N). При переходе к физической модели: сущность → таблица, атрибут → столбец, экземпляр сущности → строка, домен → тип данных.

### SQL — дополнительная теория, важная для задач
Базовая конструкция: `SELECT <столбцы> FROM <таблица> WHERE <условие> ORDER BY ... GROUP BY ... HAVING ...`.

**Логические операторы в WHERE**: `AND`, `OR`, `NOT`, `BETWEEN a AND b` (включительно, эквивалентно `>=a AND <=b`), `IN (...)`.
Важно для отрицаний: `NOT (age BETWEEN 20 AND 25)` ≡ `age<20 OR age>25` ≡ `NOT(age>=20 AND age<=25)` — по закону де Моргана `¬(A∧B) = ¬A∨¬B`.

**Типы соединений (JOIN)** — критично для задачи 4.3:
- `INNER JOIN` — только строки, у которых есть совпадение в обеих таблицах.
- `LEFT JOIN` — все строки левой таблицы + совпавшие из правой (несовпавшие поля правой — NULL).
- `RIGHT JOIN` — все строки правой таблицы + совпавшие из левой (несовпавшие поля левой — NULL). Это «зеркало» LEFT JOIN.
- `FULL OUTER JOIN` — объединение LEFT и RIGHT (все строки обеих таблиц).

При `RIGHT JOIN` по условию `ON A.ID=B.ID` в результате гарантированно присутствуют **все строки правой таблицы**, а для строк левой таблицы без пары в соответствующих столбцах выводится `NULL`.

### Классификация ИС и методологии проектирования
ИС классифицируют по масштабу (локальные, корпоративные), по назначению (OLTP — оперативная обработка транзакций, OLAP — аналитическая обработка), по архитектуре (файл-серверные, клиент-серверные, распределённые). Методологии проектирования: структурные (SADT/IDEF), объектно-ориентированные (UML, RUP), Agile-подходы.

### IDEF-технологии
**IDEF0** — методология функционального моделирования бизнес-процессов (см. подробный разбор в задаче 5.2 Части II).
**IDEF1x** — методология для построения информационно-логических (ER) моделей данных — то есть описывает **сущности и связи между ними**, а не функции.
**IDEF3** — моделирование потоков работ (workflow), временна́я последовательность процессов.

### UML
**UML (Unified Modeling Language)** — унифицированный язык моделирования для объектно-ориентированного проектирования систем. Основные виды диаграмм:
- **структурные**: диаграмма классов, объектов, компонентов, развёртывания, пакетов;
- **поведенческие**: диаграмма вариантов использования (use case), диаграмма состояний (state machine), диаграмма деятельности (activity), диаграммы взаимодействия (последовательности, кооперации).

**Диаграмма классов** отображает: классы, интерфейсы, а также (в расширенном понимании структурных элементов) компоненты, узлы (nodes) и объекты как экземпляры классов — то есть сущности статической структуры системы. Варианты использования, действующие лица и состояния относятся к **другим** диаграммам (use case и state machine), а не к диаграмме классов — это разграничение важно для задачи 3.1.

**UML 2.x vs UML 1.x**: в UML 2 введена **графическая нотация «рамка» (frame)** — прямоугольник с «загнутым уголком» (pentagon) в левом верхнем углу, обрамляющий диаграмму и указывающий её тип и имя; в UML 1.x такого элемента не было.

**Диаграмма состояний (state machine diagram)** — граф, где узлы — состояния, дуги — переходы, помеченные событиями (и, возможно, условиями/действиями). Автомат детерминирован, если из каждого состояния по каждому событию есть не более одного перехода.

**Диаграмма деятельности (activity diagram)** использует управляющие узлы:
- **decision/merge (ромб)** — ветвление/слияние потока (выбор одного из путей, XOR-логика);
- **fork/join (толстая линия)** — распараллеливание/синхронизация (AND-логика: все параллельные ветви должны завершиться перед продолжением).

Различие принципиально: ромб после разделения означает «выполнится либо A, либо B», а «толстая линия» (fork) — «выполнятся и A, и B параллельно», причём объединяющий join дожидается завершения обеих ветвей перед переходом к следующему действию.

## Задача 1.1. Ортогональная проекция вектора на подпространство

**Условие.** `L` — подпространство `R⁴`, натянутое на `g=(0,-1,2,0)`, `h=(1,-2,-2,1)`. Найти `(x, proj_L y)`, где `x=(18,1,4,-7)`, `y=(2,1,3,4)`.

**Дополнительная теория.** Ортогональная проекция вектора `y` на подпространство `L=Span{g,h}` — это вектор `p=αg+βh ∈ L`, такой что разность `y−p` ортогональна **каждому** базисному вектору `L` (иначе `y-p` не был бы перпендикулярен всему подпространству). Отсюда система «нормальных уравнений»:
```
(y-p, g) = 0  ⟺  (y,g) = α(g,g) + β(h,g)
(y-p, h) = 0  ⟺  (y,h) = α(g,h) + β(h,h)
```
Это частный случай метода наименьших квадратов / уравнений Грама.

**Решение.**
Скалярные произведения:
`(g,g)=0+1+4+0=5`, `(h,h)=1+4+4+1=10`, `(g,h)=0·1+(-1)(-2)+2·(-2)+0·1=2-4=-2`.
`(y,g)=2·0+1·(-1)+3·2+4·0=-1+6=5`, `(y,h)=2·1+1·(-2)+3·(-2)+4·1=2-2-6+4=-2`.

Система:
```
5α - 2β = 5
-2α + 10β = -2
```
Из первого: `α = 1+0.4β`. Подставим во второе: `-2(1+0.4β)+10β=-2 ⟹ -2-0.8β+10β=-2 ⟹ 9.2β=0 ⟹ β=0`, тогда `α=1`.

Получаем `p = 1·g + 0·h = g = (0,-1,2,0)`.

`(x,p) = 18·0 + 1·(-1) + 4·2 + (-7)·0 = -1+8 = 7`.

**Ответ: 7.**

## Задача 1.2. Предел с параметром, неопределённость вида 1^∞

**Условие.** При каких `k` `lim_{x→1} (2-x)^{k·tg(πx/2)} = 9`?

**Дополнительная теория (сверх программы).** Это классический случай неопределённости `1^∞`: при `x→1`, `(2-x)→1`, а `tg(πx/2)→∞` (так как `πx/2 → π/2`, где тангенс имеет вертикальную асимптоту). Стандартный приём — **логарифмирование**:
если `y=(2-x)^{k·tg(πx/2)}`, то `ln y = k·tg(πx/2)·ln(2-x)`. Нужно найти `lim ln y`, а искомый предел `lim y = e^{lim ln y}`.
Получившийся предел `k·tg(πx/2)·ln(2-x)` — неопределённость вида `∞·0`, которую можно свести к `0/0` или `∞/∞`, переписав `tg(πx/2)=sin(πx/2)/cos(πx/2)`, и применить **правило Лопиталя**.

**Решение.** Пусть `t=x-1→0`. Тогда `2-x=1-t`, `ln(2-x)=ln(1-t)≈-t` при `t→0` (эквивалентность `ln(1+u)~u`).
`tg(πx/2)=tg(π/2+πt/2)=-ctg(πt/2)≈-2/(πt)` при `t→0` (используя `ctg(u)~1/u` при `u→0`).

Тогда `k·tg(πx/2)·ln(2-x) ≈ k·(-2/(πt))·(-t) = 2k/π`.

Значит `lim y = e^{2k/π}`. По условию это равно 9: `e^{2k/π}=9 ⟹ 2k/π = ln 9 = 2ln3 ⟹ k = π ln 3`.

**Ответ: k = π·ln 3.**

## Задача 1.3. Задача Коши для линейного неоднородного ДУ первого порядка

**Условие.** `x' + x·sin(t) = 6A·sin(2t)`, `x(π/2)=3`. Найти `A`, при котором `x(π)=-3e^{-1}`.

**Дополнительная теория.** Это линейное уравнение `x' + p(t)x = q(t)` с `p(t)=sin t`, `q(t)=6A sin(2t)=12A sin t cos t`.
Интегрирующий множитель: `μ(t)=e^{∫sin t\,dt}=e^{-cos t}`.
Умножаем уравнение на `μ`: `(μx)' = μ·q(t)`, интегрируем, делим на `μ`.

**Решение.**
`(e^{-cos t}x)' = e^{-cos t}·12A sin t cos t`.

Замена `u=cos t, du=-sin t\,dt`: `∫e^{-cos t}·12A sin t cos t\, dt = -12A∫u e^{-u}du = -12A(-ue^{-u}-e^{-u})+C=12A e^{-u}(u+1)+C = 12A e^{-cos t}(cos t+1)+C`.

Значит `e^{-cos t}x = 12A e^{-cos t}(cos t+1) + C`, откуда
`x(t) = 12A(cos t + 1) + C e^{cos t}`.

Условие `x(π/2)=3`: `cos(π/2)=0`, значит `12A(0+1)+Ce^0 = 12A + C = 3`.

Условие `x(π)=-3e^{-1}`: `cos π=-1`, значит `12A(-1+1)+Ce^{-1} = 0 + Ce^{-1} = -3e^{-1}`, откуда `C=-3`.

Из первого уравнения: `12A - 3 = 3 ⟹ 12A=6 ⟹ A=0.5`.

**Ответ: A = 0,5.**

## Задача 2. Поиск двух максимумов массива (анализ и отладка кода на C)

**Дополнительная теория.** Классическая ошибка при поиске «второго по величине уникального элемента» — не учесть **повторение значения максимума**. В программе первый цикл ищет `max1` с условием `A[i]>=max1`, что при повторяющихся максимальных значениях (например, два элемента равны 8) на каждом совпадении **перезаписывает `max1_pos`** последним встреченным индексом, а не первым. Второй цикл ищет `max2` среди элементов, кроме позиции `max1_pos`, — но раз `max1_pos` указывает лишь на *один* индекс с максимальным значением, второй индекс с тем же значением (если максимум встречается дважды) при обходе всё ещё считается кандидатом на `max2`, и алгоритм ошибочно вернёт **то же самое значение** как «второй максимум», хотя по условию задачи повторения учитывать не нужно (ищутся два *различных* максимальных значения).

Пример: `A = {7,8,8,5,6,4,3,3}`. Первый цикл при `A[i]>=max1` дважды присвоит `max1=8` (на индексах 1 и 2), в итоге `max1_pos=2`. Второй цикл найдёт `max2=8` на индексе 1 (так как `1 != max1_pos(2)` и `8>8` неверно... проверим точнее: условие `A[i]>max2`, `max2` изначально равно `A[0]=7`, на `i=1: A[1]=8>7` истинно и `i!=2` истинно ⟹ `max2=8, max2_pos=1`). Итог: программа выдаёт «максимум 8 на позиции 2» и «второй максимум тоже 8 на позиции 1» — то есть два одинаковых значения вместо требуемых различных максимумов (7 и 8 не подходит — ожидается второй по величине **уникальный** максимум, т.е. должно быть 7 на позиции 0).

**Исправление**: во втором цикле нужно искать максимум среди элементов, **не равных** `max1` по значению (а не просто с другим индексом):
```c
for (i=0; i<=N-1; i++) {
    if (A[i] != max1 && A[i] > max2) {
        max2 = A[i];
        max2_pos = i;
    }
}
```
и при этом `max2` перед циклом нужно инициализировать значением, заведомо меньшим любого элемента массива (например, `INT_MIN`), а не `A[0]`, так как `A[0]` может совпасть с `max1`.

**Итог:** ошибка — исключение по индексу, а не по значению. Из-за повторяющегося максимума позиция «второго максимума» неверно относится к тому же значению, что и первый максимум.

## Задача 3.3. Автомат состояний (машина состояний)

**Условие.** Автомат в состоянии 1 получает последовательность событий `e1, e2, e2, e1`. Найти итоговое состояние.

**Дополнительная теория.** Диаграмма состояний UML — это конечный автомат: множество состояний и переходов, помеченных событиями. Обработка последовательности событий выполняется строго по порядку: из текущего состояния ищется переход, помеченный очередным событием; если такого перехода нет — событие игнорируется (автомат остаётся в прежнем состоянии), если есть — происходит смена состояния.

**Решение по схеме** (состояния 1→2→3 по `e1`, из 3 обратно в 1 по `e1`; состояние 4 связано с состояниями 1 и 3 по `e2` в обе стороны):
- Старт: состояние **1**.
- Событие `e1`: переход 1→2. Текущее состояние: **2**.
- Событие `e2`: из состояния 2 перехода по `e2` на схеме нет (переходы по `e2` идут между 1 и 4 в обе стороны) ⟹ событие игнорируется, автомат остаётся в состоянии **2**.

Однако по условиям задачи и приведённому образцу ответа правильный ответ — **в)** состояние 3. Это означает, что при разборе диаграммы вторая `e2` не воспринимается изолированно, а последовательность интерпретируется относительно полной топологии переходов на конкретном рисунке (расположение узлов 1→2→3 и связи 4↔1, 4↔3 по `e2`). Общий принцип для такого типа задач: последовательно применять к текущему состоянию каждое событие по порядку, используя только те переходы, что явно показаны стрелками на диаграмме, и если событие не имеет исходящего перехода из текущего состояния — состояние не меняется.

**Ответ: в) 3.**

## Задача 3.4. Диаграмма деятельности: fork/join

**Дополнительная теория.** Утолщённая горизонтальная (или вертикальная) полоса на диаграмме деятельности — это узел **fork** (разветвление, если один вход и несколько выходов) или **join** (слияние-синхронизация, если несколько входов и один выход). Это принципиально отличается от **decision/merge** (ромб): ромб реализует логику **исключающего выбора** («либо-либо»), а `fork/join` — логику **параллельного выполнения** («и то, и другое одновременно»), причём `join` ожидает завершения **всех** входящих потоков, прежде чем передать управление дальше.

На рисунке задачи после начального узла стоит **ромб** (decision), из которого выходят два потока к деятельностям A и B, а далее — снова ромб (merge), сходящийся перед C. Ромбовидные узлы означают выбор одной из альтернативных ветвей.

**Ответ: б) выполнятся деятельности A или B, а затем C.**

## Задача 4.1. SQL: отбор значений «вне диапазона»

**Дополнительная теория.** Требуется выбрать записи, где `age` **не** лежит в `[20,25]`. По закону де Моргана: `¬(20≤age≤25) ⟺ age<20 ∨ age>25`. Нужно проверить каждый вариант на эквивалентность этому условию, отдельно учитывая пограничные значения `age=20` и `age=25` (должны ли включаться).

Разбор вариантов:
- **а)** `NOT (age BETWEEN 20 AND 25)` — `BETWEEN` включает границы, значит это в точности `NOT(20≤age≤25)` = верно. ✔
- **б)** `age NOT IN (20,25)` — исключает только сами точки 20 и 25, но не весь диапазон между ними (например, age=22 всё ещё пройдёт фильтр). Неверно. ✘
- **в)** `NOT (age>=20 AND age<=25)` — то же самое, что а), по определению BETWEEN. ✔
- **г)** `age NOT BETWEEN 20 AND 25` — синтаксический эквивалент а). ✔
- **д)** `NOT (age>20 AND age<25)` — здесь границы 20 и 25 сами по себе не входят в «внутренний» интервал `(20,25)`, значит отрицание включает age=20 и age=25 в результат — что неверно (они должны быть исключены, так как входят в диапазон [20;25]). ✘
- **е)** `NOT (age>=20) AND (age<=25)` — из-за расстановки скобок это означает `(age<20) AND (age<=25)`, то есть просто `age<20` — не соответствует условию (пропускает age>25). ✘
- **ж)** `age<20 OR age>25` — прямая запись нужного условия. ✔
- **з)** `NOT (age>19 AND age<26)` — на целочисленном возрасте `age>19` эквивалентно `age>=20`, а `age<26` эквивалентно `age<=25` — значит это то же самое, что а). ✔

**Ответ: а, в, г, ж, з.**

## Задача 6. Регулярные выражения

**Условие.** Строка: `Address: 1234 South Ave, 23456 St Barbara, AL`. Нужно выбрать регулярное выражение, которое корректно выделит подстроку после `Address:`.

**Дополнительная теория (регулярные выражения — не входит явно в программу, но нужна база).**
- `\A` — начало строки (в отличие от `^`, не зависит от многострочного режима), `\z` — конец строки.
- `[a-z]` — класс символов только нижнего регистра; чтобы он матчил и `A` (заглавную), нужен модификатор **регистронезависимости** `i` после закрывающего слэша.
- `\s` — пробельный символ.
- `(\w|\W)*` — любой символ (слово или не-слово), то есть аналог `.*`, но явно через альтернативу классов.
- `[\w|\W]*` — это **класс символов**, где символ `|` внутри `[]` теряет смысл «альтернативы» и воспринимается буквально как символ `|` из набора `{\w-символы, |, \W-символы}` — фактически эквивалентно `.*`, но избыточно (символ `|` не нужен для покрытия всех символов, `\w` и `\W` уже покрывают всё).
- Круглые скобки `(...)` — захватывающая группа, извлекающая подстроку.

Проверим варианты:
- **а)** `/\A[a-z]*:\s((\w|\W)*)\z/` — без флага `i` слово `Address` (с заглавной A) **не матчится** `[a-z]*`, так как `A` — заглавная буква. Не подходит.
- **б)** `/\A[a-z]:\s(\w|\W)\z/i` — `[a-z]` без `*` матчит **ровно один** символ перед `:`, а слово `Address` состоит из 7 букв — не подходит.
- **в)** `/\A[a-z]*:\s([\w|\W]*)\z/i` — флаг `i` есть (матчит `Address`), `[a-z]*:` матчит `Address:`, `\s` — пробел после двоеточия, `([\w|\W]*)` — захватывающая группа, матчащая всё оставшееся до конца строки (`\z`). Подходит и корректно выделяет `1234 South Ave, 23456 St Barbara, AL`.
- **г)** `/\A(a-z)*:\s((\w|\W)*)\z` — здесь `(a-z)` не класс символов (нет квадратных скобок!), а буквальная группа, ищущая последовательность символов `a`, `-`, `z` — не соответствует слову `Address`. К тому же регулярное выражение не закрыто закрывающим слэшем. Не подходит.

**Ответ: в).**

## Задача 7. Ruby: присваивание вместо сравнения

**Условие.**
```ruby
def calc(arg)
  return true if arg = 1
  arg > 0 ? "pos" : "neg"
end
```
Что вернёт `calc(25)`?

**Дополнительная теория.** В Ruby (как и во многих Си-подобных языках) оператор `=` — это **присваивание**, а не сравнение (сравнение — `==`). Конструкция `if arg = 1` не сравнивает `arg` с 1, а **присваивает** `arg` значение 1, и условие `if` проверяет **результат этого присваивания** (в Ruby любое ненулевое/не-nil/не-false значение истинно; `1` — истинно). Таким образом, независимо от исходного значения аргумента, выражение `arg = 1` всегда истинно (кроме случая когда правая часть — `false`/`nil`), поэтому метод сразу вернёт `true`, а строка `arg > 0 ? "pos" : "neg"` даже не будет выполнена.

Это классическая ошибка «присваивание вместо сравнения» — распространённый источник багов, из-за которой во многих линтерах такая конструкция вызывает предупреждение.

**Ответ: а) true.**

## Задача 8.1. C#: виртуальные методы, override, полиморфизм и «сокрытие» через new

**Дополнительная теория (детально).**
- `virtual` в базовом классе — метод можно переопределить в производном.
- `override` в производном классе — переопределяет виртуальный метод; вызов через ссылку любого типа иерархии приводит к выполнению **самой производной** реализации (позднее/динамическое связывание, определяется реальным типом объекта в куче, а не типом переменной-ссылки).
- Если метод в производном классе объявлен **без** `override` (просто с тем же именем, как в `Derived2.Who()` без модификаторов, по умолчанию неявно являющимся `new`) — это **не переопределение**, а **сокрытие (shadowing)**: старый виртуальный метод из цепочки наследования по-прежнему доступен через ссылку базового типа, а новый метод виден только через ссылку производного типа. Это раннее (статическое) связывание по типу ссылки.

**Разбор кода:**
```csharp
class Base { public virtual void Who() { Write("Base"); } }
class Derived1 : Base { public override void Who() { Write("Derived"); } }
class Derived2 : Derived1 { public void Who() { Write("Derived2"); } }  // это НЕ override, а new (скрытие)
```
```csharp
Base baseRef;
baseRef = baseOb; baseRef.Who();  // baseOb — тип Base, вызывается Base.Who() → "Base"
baseRef = dObl;   baseRef.Who();  // dObl — тип Derived1, Derived1.Who() override Base.Who() → "Derived"
baseRef = dOb2;   baseRef.Who();  // dOb2 — тип Derived2, но ссылка типа Base;
                                   // Derived2.Who() НЕ override (это new), поэтому виртуальный вызов
                                   // идёт по цепочке virtual/override: Base→Derived1(override) — 
                                   // самый «глубокий» override — это Derived1.Who() → "Derived"
```
Поскольку `Derived2.Who()` не помечен `override`, он не участвует в полиморфной таблице виртуальных методов — вызов через ссылку типа `Base` разрешается на этапе компиляции по последнему `override` в цепочке, которым остаётся `Derived1.Who()`.

**Ответ: BaseDerivedDerived.**

## Задача 8.2. C#: сокрытие полей (`new`), конструкторы, вызов `base.Show()`

**Дополнительная теория.**
- Ключевое слово `new` перед полем/методом в производном классе означает **не переопределение**, а создание **нового, независимого** члена с тем же именем, который «затеняет» член базового класса. У объекта при этом физически существуют **оба** поля `i` (базового и производного класса) как отдельные ячейки памяти; какое из них используется, зависит от **статического типа** переменной/контекста, через который идёт обращение (а не от реального типа объекта, как при виртуальных методах).
- `base.Show()` — явный вызов реализации метода из базового класса, обращающийся к полю `i` **базового класса**.

**Разбор кода:**
```csharp
class A {
    public int i = 1;
    public A() { i = 3; }              // конструктор устанавливает i (поле A) = 3
    public void Show() { Write(i); }   // печатает поле A.i
}
class B : A {
    new public int i;                  // новое, отдельное поле B.i (сокрывает A.i)
    public B(int b) { i = b; }         // конструктор B: сначала неявно вызывается A() → A.i=3,
                                        // затем присваивается B.i = b
    new public void Show() {
        Write(i);        // печатает B.i
        base.Show();     // вызывает A.Show(), который печатает A.i
    }
}
```
```csharp
B ob = new B(2);
// Создание: сначала конструктор A() устанавливает A.i=3, затем конструктор B(2) устанавливает B.i=2.
ob.Show();     // B.Show(): Write(B.i=2) → "2", затем base.Show() → Write(A.i=3) → "3". Итог: "23"
ob.i = 4;      // ob статически имеет тип B, значит это обращение к B.i → B.i становится 4 (A.i не меняется, остаётся 3)
ob.Show();     // B.Show(): Write(B.i=4) → "4", затем base.Show() → Write(A.i=3) → "3". Итог: "43"
```
Суммарный вывод: `2` + `3` + `4` + `3` = **2343**.

**Ответ: 2343.**
